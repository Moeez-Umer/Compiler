## 2. Goal

Build the front-end of a compiler for **SmartLang**, a simplified imperative language:
lexical analyzer, parser, semantic analyzer, and a three-address-code (TAC) generator.

Input: ONE source file (`.sl`).
Output, in this order: (1) tokens, (2) parse tree, (3) symbol tables,
(4) error reports, (5) three-address code.

## 5. Lexical specification

**Whitespace** is skipped. **Comments**: `// to end of line` and `/* ... */` (non-nesting).
Line numbers start at 1, columns start at 1.

**Keywords** (token type KEYWORD):
`int float char bool const if else for while return true false`
(`true` and `false` are KEYWORD tokens; the parser turns them into bool literals.)

**Identifiers**: `[A-Za-z_][A-Za-z0-9_]*`, not a keyword.

**Literals**
- INT_LIT: `[0-9]+`
- FLOAT_LIT: `[0-9]+ '.' [0-9]+` (digits required on both sides)
- CHAR_LIT: one character in single quotes, or an escape: `'a'`, `'\n'`, `'\t'`, `'\\'`, `'\''`, `'\0'`

**Operators** (OPERATOR): `+ - * / % = == != < > <= >= && || !`
Longest match wins (`<=` not `<` then `=`).

**Delimiters** (DELIMITER): `( ) { } ; ,`

**Invalid tokens** (emit an INVALID token, report a Lexical Error with line, continue):
- unknown character: `@ # $ ~ ^ ? : . [ ] \` and similar
- single `&` or single `|`
- malformed number: `3.4.5`, `3.`, `.5`
- number glued to letters: `9abc`
- char literal: unterminated `'a`, empty `''`, too long `'ab'`, bad escape `'\q'`
- unterminated block comment (report at the line where it started)

## 6. Grammar (LL(1), left recursion removed, left-factored)

```
program      → topLevel* EOF
topLevel     → 'const' type ID varRest
             | type ID ( funcRest | varRest )
varRest      → ( '=' expr )? ';'
funcRest     → '(' params? ')' block
params       → param ( ',' param )*
param        → type ID
type         → 'int' | 'float' | 'char' | 'bool'

block        → '{' statement* '}'
statement    → varDecl | idStmt | ifStmt | whileStmt | forStmt | returnStmt | block
varDecl      → 'const'? type ID ( '=' expr )? ';'
idStmt       → ID ( '=' expr | '(' args? ')' ) ';'
ifStmt       → 'if' '(' expr ')' block ( 'else' ( ifStmt | block ) )?
whileStmt    → 'while' '(' expr ')' block
forStmt      → 'for' '(' forInit? ';' expr ';' forUpdate? ')' block
forInit      → type ID '=' expr | ID '=' expr
forUpdate    → ID '=' expr
returnStmt   → 'return' expr ';'
args         → expr ( ',' expr )*

expr         → orExpr
orExpr       → andExpr ( '||' andExpr )*
andExpr      → eqExpr ( '&&' eqExpr )*
eqExpr       → relExpr ( ( '==' | '!=' ) relExpr )*
relExpr      → addExpr ( ( '<' | '>' | '<=' | '>=' ) addExpr )*
addExpr      → term ( ( '+' | '-' ) term )*
term         → unary ( ( '*' | '/' | '%' ) unary )*
unary        → ( '-' | '!' ) unary | primary
primary      → INT_LIT | FLOAT_LIT | CHAR_LIT | 'true' | 'false'
             | ID ( '(' args? ')' )?
             | '(' expr ')'
```

Notes
- Braces are mandatory on every block (no dangling-else problem).
- Assignment is a statement, not an expression. No `++`, `+=`, ternary.
- Functions exist only at top level (no nesting). There is no `void`; every function returns a value.
- Precedence, high to low: unary `- !` > `* / %` > `+ -` > `< > <= >=` > `== !=` > `&&` > `||`.
  All binary operators are left associative.

## 7. Parse tree

The parser builds a tree of node classes (see interfaces.md). Node names mirror grammar rules.
Chains of single-child expression levels are collapsed (no ten-deep `orExpr→andExpr→...` chain)
so the printed tree stays readable. This is recorded in Decisions.md.

Exports: indented text (`--tree`) and Graphviz PNG (`--tree-png PATH`).

## 8. Semantic rules

**Types**: `int`, `float`, `char`, `bool`, plus an internal `error` type used to suppress
cascading errors (an expression with type `error` never triggers further errors).

**Literal types**: INT_LIT is int, FLOAT_LIT is float, CHAR_LIT is char, true/false is bool.

**Assignability** (value type → target type), used by assignment, initializers, arguments, return:
| value \ target | int | float | char | bool |
|---|---|---|---|---|
| int   | yes | yes | NO  | NO |
| float | NO (error: no cast in SmartLang) | yes | NO | NO |
| char  | yes | yes | yes | NO |
| bool  | NO  | NO  | NO  | yes |

**Expression typing**
| Construct | Operand rule | Result |
|---|---|---|
| `+ - * /` | both numeric (int, float, char) | float if either is float, else int |
| `%` | both int or char (no float) | int |
| unary `-` | numeric | int (for int/char) or float |
| `< > <= >=` | both numeric | bool |
| `== !=` | both numeric, or both bool | bool |
| `&& \|\|` | both bool | bool |
| `!` | bool | bool |
| call `f(a,b)` | see function rules | f's return type |

`bool` is never allowed in arithmetic. char is promoted to int in arithmetic.

**Conditions**: the condition of `if`, `while`, `for` must have type bool.

**Declarations and scope**
- Scopes: global, function (parameters AND the function body's top-level share one scope), block.
- A `for` statement opens its own scope that contains the init variable.
- Redeclaring a name in the SAME scope is an error. Shadowing an outer scope is allowed.
- Using an undeclared identifier is an error. Lookup walks from innermost scope outward.
- `const` must have an initializer and cannot be assigned after declaration.
- A function name cannot be used as a variable, and a variable cannot be called.

**Functions**
- Signatures of ALL top-level functions are collected first (pass 1), so calls to functions
  defined later and recursion are legal.
- Duplicate function names are an error.
- A call must match the number of parameters; each argument must be assignable to its parameter type.
- Every `return` expression must be assignable to the declared return type.
- The last statement of a function body (top level of the body) must be a `return`;
  otherwise report "missing return" at the function's closing brace line.

**Not checked** (documented limitation): use of uninitialized variables, unreachable code,
division by literal zero.

## 9. Error handling

Format (exact):
```
[Lexical Error] Line 5, Col 12: Invalid character '@'
[Syntax Error] Line 9, Col 1: Expected ';' but found '}'
[Semantic Error] Line 14, Col 5: Cannot assign float to int variable 'x'
```
- Every error has a line number. The compiler NEVER crashes or hangs on any input.
- Collect as many independent errors as possible per run.
- Syntax recovery is panic mode: record error, skip to a synchronizing token
  (`;`, `}`, or a statement-starting keyword), continue. Guarantee forward progress.
- Pipeline policy: lexical and syntax errors stop the pipeline after parsing
  (semantic analysis and TAC are skipped). Semantic errors skip TAC.
  Tokens are always printed; the tree is printed if the parser produced one.
- Output order of the error section: Lexical, then Syntax, then Semantic, each sorted by line, col.

## 10. Symbol tables

Each symbol: name, type, kind (`var`, `const`, `param`, `func`), scope level, line,
and for functions: return type and parameter list. The final output prints EVERY scope
that existed (including exited ones), labelled e.g. `Scope 0 (global)`, `Scope 1 (function sumSquares)`,
`Scope 2 (block)`.

## 11. Three-address code

Instruction forms (one per line, instructions indented two spaces, labels and `func` at column 0):
```
x = y
x = y op z            op in: + - * / % < > <= >= == != && ||
x = op y              op in: - !
goto L
ifFalse x goto L
L:
param x
x = call f, n         (n = number of arguments)
call f, n             (result unused)
return x
func name:            ... endfunc
```
- Temporaries `t1, t2, ...` and labels `L1, L2, ...` are numbered per program, in order of creation.
- Global declarations with initializers are emitted first under a `globals:` header.
- `&&` and `||` are emitted as plain binary instructions (NO short-circuit). Recorded in Decisions.md.
- No explicit int-to-float conversion instructions.
- Shadowing: the semantic analyzer assigns each declared variable a unique `tac_name`
  (`x`, then `x_1`, `x_2` for shadowing declarations); TAC uses it.
- TAC is generated ONLY when there are zero errors.

Shapes:
```
if (c) A else B        while (c) A            for (init; c; upd) A
  t1 = <c>               L1:                    <init>
  ifFalse t1 goto L1     t1 = <c>               L1:
  <A>                    ifFalse t1 goto L2     t1 = <c>
  goto L2                <A>                    ifFalse t1 goto L2
L1:                      goto L1                <A>
  <B>                  L2:                      <upd>
L2:                                             goto L1
                                              L2:
```
`else if` chains nest the same shape. Without `else`, no `goto L2` and no `<B>`.

## 12. CLI

```
python src/main.py prog.sl [--tokens] [--tree] [--tree-png PATH] [--symbols] [--tac] [--all]
```
No flag means `--all` (everything except the PNG). Section headers: `== TOKENS ==`, `== PARSE TREE ==`,

Exit code: 0 no errors, 1 any compile error, 2 usage or file error.

## 14. Sample valid program

```c
const int LIMIT = 10;

int square(int x) {
    return x * x;
}

int sumSquares(int n) {
    int total = 0;
    int i = 1;
    while (i <= n) {
        total = total + square(i);
        i = i + 1;
    }
    return total;
}

float average(int a, int b) {
    float s = a + b;
    return s / 2;
}

int main() {
    int r = sumSquares(LIMIT);
    bool big = r > 100 && LIMIT != 0;
    if (big) {
        r = r - 1;
    } else if (r == 0) {
        r = 1;
    } else {
        r = 0;
    }
    for (int k = 0; k < 3; k = k + 1) {
        r = r + k;
    }
    return r;
}
```
